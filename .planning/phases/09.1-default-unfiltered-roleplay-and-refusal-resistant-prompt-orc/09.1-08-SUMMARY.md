## Decisions Made

- The inspector reports an explicit `seed_policy` string instead of generating, storing, or exposing any numeric seed. Actual runtime seed allocation remains exclusively inside real generation attempts.
- Configured sampler values are presented separately from the effective provider request. This keeps user-selected values inspectable while `omitted_fields` truthfully explains what a generic adapter does not transmit.
- Continue preview follows production semantics exactly: nonempty composer text becomes the assistant prefill; an empty composer uses the selected assistant version; Regenerate and Swipe stop before their target response.
- Refusal activity is scoped to the requested thread and projected from the bounded process-local ring through a strict metadata model. No prompt, history, generated text, rejected text, correction prose, or seed is available to the response mapper.

## Security and Privacy

- The endpoint is same-origin, strict-body, no-store, and content-scoped to the requested local thread; message targets are rejected if they belong to another thread.
- The response is a positive allowlist. API keys, Authorization headers, base URLs, endpoint credentials, raw private paths, numeric runtime seeds, hidden diagnostics, correction prose, generated/rejected prose, and lorebook/world-info never enter success or error DTOs.
- Preview invokes only saved-settings reads, immutable thread/message hydration, the shared pure composer, and the shared pure adapter. Generation clients, provider streams, runtime seed factories, settings/history writes, and persistence remain untouched.
- Cancellation is unshielded and cooperative; barrier-synchronized concurrent previews keep their exact content isolated and leave durable state byte-for-byte unchanged.
