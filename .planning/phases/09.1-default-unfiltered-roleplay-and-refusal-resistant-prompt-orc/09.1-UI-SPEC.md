# Phase 09.1 — UI Design Contract

> Visual and interaction contract for the Prompt & Generation Settings panel, Character Editor prompt help, and text-thread Prompt Inspector. Generated by gsd-ui-researcher; verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | Manual, project-native Svelte 5 components and CSS tokens |
| Preset | Not applicable |
| Component library | Project-native Svelte components; no shadcn/Radix/Base UI |
| Icon library | `lucide-svelte@1.0.1`, 18px default, `strokeWidth={1.8}` |
| Font | Manrope for headings/display; Inter for body, labels, controls, and prompt prose |

The source of truth is `web-ui/client/src/app.css` plus `docs/stitch/DESIGN.md`. New work must extend the existing Ethereal Core / True Dark language rather than restyle adjacent screens.

The shadcn initialization gate is not applicable: this is an established SvelteKit UI with a source-owned Svelte component system, not a React shadcn project. `components.json` is absent by design.

- Use tonal nesting instead of section borders: `surface` → `surface-low` → `surface-high` → `surface-highest`.
- Do not add opaque 1px dividers. A ghost inset outline may use `--color-outline-ghost` at the existing low opacity only where a field or dialog needs definition.
- Floating inspector UI follows the brand glass rule: `surface-highest` at 60% opacity, `backdrop-filter: blur(20px)`, and `--shadow-float`. Dense text sits on nested tonal panes for contrast; the outer floating surface does not exceed 60% opacity.
- Inputs use a filled dark surface, never a white field. Focus uses the existing 2px violet focus outline.
- Preserve the current AppShell, top bar, desktop rail, and mobile bottom navigation. This phase adds no top-level destination.
- Apply the brand font roles once at the app-level stylesheet: bundle/load Manrope locally for every Heading/Display role and retain Inter for Body/Label/control roles. Do not scope Manrope to only these phase components and do not fetch fonts from a runtime CDN.

## Spacing Scale

Declared values (all spacing values are multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| `xs` | 4px | Icon/text gaps, chip internals |
| `sm` | 8px | Compact control groups, field label-to-control gap |
| `md` | 16px | Default field and list spacing |
| `lg` | 24px | Panel padding and section gaps |
| `xl` | 32px | Page and full-width panel gaps |
| `2xl` | 48px | Major section separation |
| `3xl` | 64px | Page-level breathing room only |

Exceptions: every interactive control has a 44px minimum width and height; 44px is a touch-target dimension, not a spacing token. Safe-area insets may add device-defined space. Do not introduce arbitrary 6px, 10px, 14px, or 20px layout gaps in new phase UI.

## Typography

Use exactly the brand's four sizes and two weights. Manrope owns Heading and Display; Inter owns Body, Label, and all control copy. Prompt bodies and inspector values use Body, never Label.

| Role | Family | Size | Weight | Line Height |
|------|--------|------|--------|-------------|
| Body | Inter | 14px | 400 | 1.5 |
| Label | Inter | 12px | 600 | 1.3 |
| Heading | Manrope | 20px | 600 | 1.2 |
| Display | Manrope | 28px | 600 | 1.15 |

- Use Label for field names, chips, bounds, and metadata keys.
- Use Body for descriptions, prompt text, JSON, errors, and helper copy.
- Prompt prose uses Inter. A monospace stack may be used only inside `<code>`/`<pre>` values such as exact JSON and macro tokens. Do not reduce those panes below 14px.
- Long prompt text must preserve line breaks, wrap at arbitrary strings, and remain selectable.

## Surface Contracts

### 1. Settings — Prompt & Generation

The route heading becomes **Settings**, not **Endpoint Settings**. The existing `Save Settings` action remains the single page-level commit action and persists endpoint, audio, VAD, prompt, profile, and generation values together. Nothing in the new panel auto-saves.

Place a full-width Prompt & Generation panel after the existing endpoint/readiness and audio/VAD groups. On desktop it spans the Settings grid; on mobile it remains a single column. The panel uses `surface-high`, 24px padding, an 8px internal heading gap, and 24px between subsections.

Panel header:

- Eyebrow: **LLM behavior**
- Heading: **Prompt & Generation**
- Description: **Choose how RayMe composes character requests and tune the bounded generation settings used by text and calls.**

**Primary visual anchor — prompt-mode selector:** the three Roleplay/Assistant/Custom cards are the Settings surface's dominant visual object. The selected card carries a 4px left pulse-gradient strip, checked radio, and mode chip; unselected cards stay on the secondary tonal surface. Roleplay's selected-by-default treatment must be legible before the eye reaches the prompt fields or sampler grid.

#### Mode selection

Use a `<fieldset>` with a visible legend and three real radio inputs presented as equal tonal cards:

| Mode | Visible label | Supporting copy | State contract |
|------|---------------|-----------------|----------------|
| `roleplay` | **Roleplay** + **Default** chip | **Write the selected character's next in-world reply without AI or policy commentary.** | Selected when the setting is absent, including for existing threads. Violet active surface and checked radio are visible on first ready render. |
| `assistant` | **Assistant** | **Use a conventional helpful-assistant prompt.** | Deliberate global alternative; never selected automatically. |
| `custom` | **Custom** | **Use your own Main, Auxiliary, and late post-history prompts.** | Deliberate global alternative; Main is required when this mode is saved. |

- Stack the three cards below 640px; use three equal columns at 640px and above.
- Each mode card is at least 56px high and has a 44px minimum hit area across its full surface.
- Switching modes changes only the visible editor and local form selection. It preserves unsaved text in every mode until save or page reload.
- Loading settings must show the existing page skeleton; do not flash Assistant, Custom, or an unselected state before Roleplay resolves.
- The active mode does not change the model profile, samplers, context limit, or Qwen no-thinking toggle.

#### Prompt editors and reset

Each mode owns three labeled multiline fields in this fixed order:

1. **Main prompt** — primary behavioral contract.
2. **Auxiliary prompt** — independently ordered private-fiction/behavior guidance.
3. **Post-history instruction** — the late instruction placed after real history.

Roleplay and Assistant load their shipped built-in text and may be deliberately edited. A `Built-in preset` chip remains visible; add a `Modified` chip when any of the three values differs from the shipped version. Custom stores a separate set and never overwrites either built-in preset.

- Textareas are 100% width, minimum 144px and maximum 320px high, vertically resizable, and render all content as plain text.
- Main, Auxiliary, and post-history fields for Roleplay and Assistant may not be saved blank. Custom Main is required; Custom Auxiliary and post-history may be blank by design.
- A blank required prompt shows its field- and mode-specific sentence from the **Validation and empty-state copy matrix**; do not collapse these failures into a generic “required” banner.
- An inline **Reset Roleplay Prompts** or **Reset Assistant Prompts** secondary action appears only for its matching built-in mode. It is disabled while values match the shipped version.
- Reset opens the existing confirmation-dialog pattern. It resets only that mode's three prompt fields; it does not change the active mode, Custom fields, samplers, model profile, or endpoint settings.
- Cancel receives initial focus. After confirmation, focus returns to the reset trigger and a polite status announces **Roleplay prompts reset to built-in defaults.** or **Assistant prompts reset to built-in defaults.** The reset remains local until `Save Settings` is pressed.
- Do not offer an ambiguous global **Reset all** action in this phase.

#### Model profile

Render one labeled native select with these exact visible options and descriptions:

| Value | Label | Description |
|-------|-------|-------------|
| `auto` | **Auto (recommended)** | Resolve from the configured model ID; the inspector shows the resolved profile. |
| `qwen_llama_server` | **Qwen / llama-server** | Include supported local samplers and merged Qwen no-thinking fields. |
| `generic_openai_compatible` | **Generic OpenAI-compatible** | Send only standard, supported request fields. |

Move the existing **Disable Qwen thinking** toggle into this subsection. Preserve its saved value across profile switches. When the explicit Generic profile is selected, show it disabled with helper copy **Used only when Auto resolves to Qwen or Qwen / llama-server is selected.** Never mutate stored conversation text with `/no_think`.

#### Bounded context and generation controls

Use numeric inputs, not free-form text. Each input has a persistent helper showing `Default`, `Min`, `Max`, and `Step`. Inputs are 44px high, expose native increment/decrement behavior, and show an inline validation message rather than silently submitting a clamped value.

| Field label | Default | Min | Max | Step | Helper purpose |
|-------------|---------|-----|-----|------|----------------|
| **Context limit** | 16,384 | 2,048 | 131,072 | 1,024 | Estimated total context capacity configured for the running server. |
| **Maximum output tokens** | 512 | 64 | 4,096 | 64 | Reserved before prompt/history budgeting. |
| **Temperature** | 0.80 | 0.00 | 2.00 | 0.05 | Higher values increase variation. |
| **Top-p** | 0.95 | 0.01 | 1.00 | 0.01 | Nucleus sampling probability mass. |
| **Min-p** | 0.05 | 0.00 | 1.00 | 0.01 | Qwen/llama-server minimum probability filter. |
| **Top-k** | 40 | 0 | 200 | 1 | Candidate-token limit; 0 disables it where supported. |
| **Repetition penalty** | 1.05 | 0.50 | 2.00 | 0.01 | Discourages repeated phrasing. |
| **Presence penalty** | 0.00 | -2.00 | 2.00 | 0.10 | Adjusts reuse based on whether a token appeared. |
| **Frequency penalty** | 0.00 | -2.00 | 2.00 | 0.10 | Adjusts reuse based on how often a token appeared. |

Layout is two columns at 720px and above and one column below. Context and output controls appear first as a pair; sampler controls follow. A static row states **Seed: Fresh random value generated for every attempt.** There is no seed input in ordinary Settings.

Validation behavior:

- `Save Settings` is disabled only while saving or while a visible prompt/generation field is invalid.
- Every invalid field receives `aria-invalid="true"` and an error tied with `aria-describedby`.
- Every out-of-range or off-step numeric value uses the exact field-specific sentence in the **Validation and empty-state copy matrix**; do not substitute browser-default validation prose.
- The first invalid field receives focus after a rejected save attempt.
- If required prompt sections cannot fit the configured budget, preserve all entered text and show the typed budget error; never silently trim mandatory prompt fields.
- Successful save copy changes from endpoint-specific wording to **Settings saved.**
- Failed save copy is **RayMe could not save settings. Your changes are still here. Try again.**

### 2. Character Editor — Prompt Macro Help

Keep the existing two-column Character Editor and `Save Character` flow. Add prompt guidance inside existing sections; do not create another editor screen or a hidden tooltip-only explanation.

Under **Example messages**, add persistent helper copy:

> Separate example scenes with `<START>`. Prefix turns with `{{user}}:` and `{{char}}:`. RayMe keeps each scene together when context is trimmed.

At the top of **System and notes**, add a compact tonal callout titled **Prompt macros** with three definition rows:

| Token | Visible definition |
|-------|--------------------|
| `{{char}}` | Current character name. |
| `{{user}}` | Current user name. |
| `{{original}}` | Active global Main or post-history prompt; expanded before the name macros. |

End the callout with **Macros expand once. Unknown macros remain unchanged.** Render tokens with `<code>` and all field/help content through ordinary Svelte text interpolation. `{@html}` and raw HTML insertion are forbidden.

Add reactive source guidance below **System prompt** and **Post-history instruction**:

- Blank field: **Blank: inherits the active global prompt.**
- Nonblank field without `{{original}}`: **Overrides the active global prompt. Add `{{original}}` to include it.**
- Nonblank field with `{{original}}`: **Includes the active global prompt at `{{original}}`.**

Under **Post-history instruction**, always add:

> Runs after the selected conversation history as the late post-history instruction (PHI), sometimes called a jailbreak.

The help is informational and never mutates card fields. It wraps at 320px, remains visible in create/review/edit modes, and uses muted Body text rather than tiny labels. Existing Discard/Save/portrait/voice behavior is unchanged.

### 3. Text Thread — Prompt Inspector

Add a visible **Inspect Prompt** control to the text-thread header. Use a Lucide inspection/code icon plus text at 800px and above and an icon-only 44px button with `aria-label="Inspect Prompt"` below 800px. It must expose `aria-haspopup="dialog"` and `aria-expanded`.

Header priority on narrow screens is: Back, identity, Inspect Prompt, Start Call. Move **Reload thread** into a 44px overflow menu below 520px rather than shrinking the title or any control below 44px. At 520px and above, Reload remains a separate icon action.

**Primary visual anchor — ordered-request spine:** the Inspector's dominant object is the Ordered messages stack, marked by a 4px violet-to-cyan pulse-gradient spine beside its numbered role cards. Request summary and controls remain quieter tonal blocks so the actual role/content order is the first scannable result. The spine is an ordering indicator, not a section border, and remains visible in the mobile sheet.

#### Drawer shell

The control opens a right-edge drawer on desktop and a full-screen sheet below 640px:

- Desktop width: `min(760px, calc(100vw - 48px))`; full viewport height; 24px panel padding.
- Mobile: `inset: 0`, safe-area padding, width/height 100%; z-index above AppShell bottom navigation.
- Background: `surface-highest` at 60% opacity, 20px blur, ambient shadow, no opaque divider. Place prompt prose, request fields, and JSON on nested `surface-high`/`surface-low` panes so text contrast remains stable without violating the 60% floating-glass rule.
- Header and action footer remain sticky; only the drawer body scrolls.
- Title: **Prompt Inspector**.
- Intro: **Preview the exact credential-free request RayMe would build. This does not generate, save, or change anything.**
- Close is a 44px icon button with `aria-label="Close Prompt Inspector"`. Escape, backdrop, and Close remain available during preview; they abort the non-mutating preview request, close the drawer, and restore focus to the trigger.
- Trap focus while open, lock background scroll, and set the rest of the app inert/hidden from assistive technology.

Opening the drawer performs no generation, persistence, settings update, call action, microphone request, or random-seed allocation.

#### Preview controls

Use one **Variant** radio group and one dependent **Action** select:

| Variant | Actions |
|---------|---------|
| **Text** | Send, Regenerate, Swipe, Continue |
| **Call** | Call offer, Call turn |

Rules:

- Send reads the current composer draft without clearing or submitting it. A blank draft disables Preview and shows **Enter a composer draft to inspect Send.**
- Regenerate and Swipe show a **Target turn** select containing eligible assistant turns from the selected, non-stale branch.
- Continue shows a target assistant-turn select and includes the current composer draft as the final assistant prefill; a blank prefill is allowed.
- If Regenerate, Swipe, or Continue has no eligible assistant target, disable the Target turn select and Preview action and show **No assistant turns are available on the selected branch. Choose another action or add an assistant turn first.**
- Call offer needs no target and previews the current thread-to-call composition.
- Call turn shows a local-only **Preview user transcript** textarea. It is required for preview, never saved, and cleared when the drawer closes. A blank value disables Preview and shows **Enter a preview user transcript to inspect Call turn.**
- Target options use sequence plus an escaped, single-line 80-character visual summary. The actual selected turn remains complete in the result.
- Any variant/action/target/draft change marks an existing result **Preview out of date** and requires a new preview.
- The primary action is **Preview Request**. It calls only the same-origin non-mutating preview boundary and uses saved Settings plus the explicit local preview inputs.

#### Result composition

The populated result is structured in this order:

1. **Request summary** — action, active mode, resolved model profile, configured model ID, prompt-contract version, request-shape version, and `Preview only` status.
2. **Budget** — configured context, reserved output, safety margin, estimated input tokens, kept/dropped history count, kept/dropped complete example-group count, and the call 48-message ceiling when applicable. Every token figure is labeled **Estimate**.
3. **Ordered messages** — numbered rows showing exact transmitted role, section, source, override state, and full escaped content. Source labels include Global preset, Character snapshot, Example group, Selected history, Late post-history, Retry correction, and Assistant prefill as applicable.
4. **Request fields** — exact fields actually serialized for the resolved profile, including `stream`, `max_tokens`, standard samplers, and supported `extra_body` values. Omitted fields are absent rather than shown as null. `seed` renders exactly **Generated at send time**.
5. **Credential-free request JSON** — a collapsed disclosure containing the exact preview body rendered in an escaped `<pre>`. It contains no HTTP headers, API key, bearer token, credential-bearing URL, or generated runtime seed.
6. **Refusal policy** — prefix guard ceiling, maximum three attempts, late retry-correction presence, and terminal `llm_refusal_exhausted` behavior. It explicitly states that rejected prose is not displayed, spoken, persisted, or copied into retries.
7. **Recent refusal activity** — current-thread metadata rows containing action, attempt, reason code, prefix character/estimated-token counts, retry count, release time, and terminal outcome. It never shows seed, prompt/history, generated text, or rejected prose.

Ordered message content is fully available; do not use a permanent ellipsis. Per-row `<details>` collapse is allowed for navigation, but expanding a row must reveal every character. Preserve whitespace with `white-space: pre-wrap` and `overflow-wrap: anywhere`. The raw JSON pane may scroll horizontally inside itself; it must never widen the drawer or page.

Unknown macros remain visible exactly as composed. Card-supplied markup such as `<img onerror=...>` displays as characters. No inspector component may use `{@html}`, `innerHTML`, or an HTML parser.

#### Inspector states

| State | Visual and interaction contract |
|-------|---------------------------------|
| Initial | Centered low-tone empty state with **No request preview yet** and the documented next step; controls remain usable. |
| Loading | Keep controls and prior result in place, mark the result region `aria-busy="true"`, add a three-row skeleton, and disable only a duplicate Preview. Close remains available and aborts the request. |
| Populated | Render all seven result sections. Move focus to the result heading only when Preview was keyboard-initiated. |
| Stale | Keep the result visible under a muted **Preview out of date** banner; never imply it is still exact. |
| Error | Inline alert inside the drawer with retry; controls and local input remain intact. Never replace server-safe copy with a raw exception. |
| Budget failure | Show the exact budget error and preserve all selections/drafts. No partial request result is labeled exact. |
| No recent retries | Show **No refusal retries recorded for this thread.** Do not fabricate an all-clear metric. |

#### Generation feedback in the thread

Rejected prefixes remain invisible. If a retry lasts long enough to create a visible pause, the streaming bubble may show a polite metadata-only status **Keeping {character} in character — attempt 2 of 3…**; suppress this transient status for retries resolved in under 300ms to avoid flicker. Remove it as soon as accepted content streams.

Terminal typed errors use these actions:

- `llm_refusal_exhausted`: **The model stayed out of character after three attempts. Try again or inspect the prompt.** Actions: **Try Again** and **Inspect Prompt**.
- `prompt_budget_exceeded`: **This request does not fit the configured context. Raise the context limit or reduce prompt/history content, then try again.** Actions: **Open Settings** and **Inspect Prompt**.
- Invalid model profile/request: **The selected model profile could not build this request. Check Prompt & Generation settings.** Action: **Open Settings**.

These states must reuse the current failed-stream bubble pattern and keep the user's draft/scroll anchor. They must not display a rejected prefix, create an assistant message, or claim a successful call/text turn.

## Responsive and Accessibility Contract

- Support 320px viewport width without horizontal page scroll.
- Settings uses one column below 720px; prompt modes stack below 640px; numeric controls become one column below 720px.
- The inspector becomes a full-screen sheet below 640px and covers the bottom navigation. Its content uses safe-area padding at top and bottom.
- All buttons, mode cards, selects, inputs, disclosure summaries, and icon actions expose at least a 44×44px target.
- Mode and Variant selectors are native radio groups with visible legends and arrow-key behavior. Do not build them from divs.
- Drawer focus is trapped; Escape/backdrop close; focus returns to the exact trigger. Closing during preview explicitly aborts the preview request before the drawer is removed.
- Loading and success use polite live regions. Validation and request failures use `role="alert"` only when new; do not announce static helper copy as an alert.
- Color is never the only state cue: checked radio, text label, chip, and `aria-checked`/native checked state accompany accent color.
- Respect `prefers-reduced-motion`. Drawer movement becomes near-instant and no shimmer is required; skeletons remain static tonal blocks.
- Prompt text, card fields, JSON, and errors render as escaped text. No raw HTML, `{@html}`, `innerHTML`, or unsafe Markdown path is permitted.
- Do not truncate role/content values needed to verify the exact request. Navigation labels may visually ellipsize only where the full value remains available in the result or accessible name.
- Preview and inspector actions must be operable with keyboard and touch and must not depend on hover tooltips.

## Interaction and Data-Safety Invariants

1. Roleplay is visibly selected when settings are absent and remains the effective default for old and new threads until the user saves another mode.
2. Assistant and Custom are explicit selections; the UI never changes mode in response to a refusal, model profile, card content, or endpoint error.
3. Settings mode/prompt changes remain local until `Save Settings`; the Inspector always labels that it uses saved Settings.
4. Preview is non-mutating: zero generation requests, assistant rows, call rows, audio, settings writes, message edits, random seeds, or call-state changes.
5. Preview and wire composition come from the same structured build result. Any stale result is visibly marked stale.
6. API keys, authorization headers, bearer tokens, credential-bearing URLs, generated runtime seeds, raw rejected prose, and raw server exceptions never enter inspector data or the DOM.
7. Refusal metadata is allowlisted and content-free. Absence of retry metadata is shown as absence, not as proof that no retry ever occurred.
8. A safe prompt preview does not certify model behavior. It is labeled Preview only.
9. Character macro help never edits, normalizes, strips, or recursively expands stored card text.
10. Text and call previews preserve the same ordered composer semantics, including Continue's final assistant prefill and the call-offer 48-message ceiling.
