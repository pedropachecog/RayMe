# Phase 09.1 Plan 12: Typed Generation Recovery UI Summary

Allowlisted generation outcomes now drive delayed retry feedback and exact actionable failures without exposing rejected text or private upstream data.

## Performance

- **Duration:** 31m

## Accomplishments

- Added strict `GenerationFailure` and `RefusalActivity` decoders across JSON HTTP and fragmented SSE, with stable codes, exact Unicode token preservation, abort propagation, and no displayable raw server detail.
- Added a lifecycle-owned retry controller that suppresses sub-300ms retries, announces the exact metadata-only sentence when useful, and clears before accepted content renders.
- Added exact UI-SPEC terminal copy and typed Try Again, Open Settings, and Inspect Prompt intents; pre-release failures become event rows rather than successful assistant messages.
- Added call terminal-code mapping into the shared sanitized union without changing live playback, TTS, listening recovery, explicit Interrupt, disabled automatic VAD barge-in, or existing terminal-event ownership.

## Requirement Delivered Verbatim

**REQ-39** `[v1]` — **Bounded streaming refusal recovery**: RayMe detects an
explicit generic/guideline refusal in the initial streamed prefix, cancels
that attempt, and retries with corrective prompt context before the refused
text is rendered, spoken, or persisted. Normal in-character output must be
released after a small bounded prefix guard; neither text nor calls may wait
for the full LLM response, and live-call early playback, listening recovery,
and explicit interruption remain mandatory.
