Call offers and turns now share the configured structured composer and adapter, while accepted captions and streaming audio still start early and rejected or empty model text reaches no live or durable sink.

- Replaced the legacy call prompt helper with one request-owned structured generation snapshot for both `call_offer` and `call_turn` actions, carrying persisted prompt settings and the effective adapter.
- Enforced the AI-backend offer limits only after adapter mapping, returning typed mandatory overflow without applying the 48-message ceiling to ordinary call turns.

## Decisions Made

- Offer preparation and turn generation share composer inputs and adapter configuration, but only real turn attempts own runtime seeds and retries. The offer's adapter serialization uses a non-transmitted deterministic seed because the AI backend consumes only the mapped prompt messages.
- Offer limits are checked on the final adapter messages in addition to composer-side locked drops. A profile mapping that combines mandatory messages past 20,000 characters fails with the existing typed prompt-budget contract.
- Leading whitespace is not itself usable call content. It is held until the first accepted visible token and then released byte-for-byte with that token; if no visible token arrives, it is discarded before the sanitized failure.

## Requirements Delivered (Verbatim)

- **REQ-37** `[v1]` — **Default character roleplay contract**: every new and existing character conversation resolves to the Roleplay prompt preset unless the user explicitly selects Assistant or Custom. Blank card-level Main or post-history fields inherit the active preset. The default instructs the LLM to produce the selected character's next in-world reply and must not silently fall back to generic helpful-assistant identity or guideline-refusal boilerplate.
- **REQ-38** `[v1]` — **Shared SillyTavern-class prompt composer**: text and live-call generation use one ordered, token-budgeted composer supporting global Main, Auxiliary, and late post-history prompts; character overrides with `{{original}}`; at least `{{char}}` and `{{user}}` macros; injected example dialogue; model-aware message roles; explicit sampler controls; and an exact effective-request inspector that excludes credentials. Thread snapshots preserve character identity but must not freeze obsolete global prompt defaults.
- **REQ-39** `[v1]` — **Bounded streaming refusal recovery**: RayMe detects an explicit generic/guideline refusal in the initial streamed prefix, cancels that attempt, and retries with corrective prompt context before the refused text is rendered, spoken, or persisted. Normal in-character output must be released after a small bounded prefix guard; neither text nor calls may wait for the full LLM response, and live-call early playback, listening recovery, and explicit interruption remain mandatory.
