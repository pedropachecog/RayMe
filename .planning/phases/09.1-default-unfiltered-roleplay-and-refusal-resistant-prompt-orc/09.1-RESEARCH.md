### Locked Decisions

### Prompt Modes, Defaults, And Inheritance

- **D-01:** `roleplay` is the persisted application default and applies live to
  new and existing threads. Global prompt settings are not frozen into thread
  snapshots, so this repair immediately reaches old conversations.
- **D-02:** Settings exposes three explicit modes: **Roleplay** (default),
  **Assistant**, and **Custom**. Mode selection is global in this phase;
  per-thread preset selection is deferred.
- **D-03:** The built-in Roleplay Main prompt tells the model to write only
  `{{char}}`'s next reply in the ongoing fictional scene with `{{user}}`, treat
  the card/scenario/examples/history as authoritative, stay fully in character,
  and omit AI, prompt, policy, or meta commentary.
- **D-04:** The built-in Roleplay Auxiliary prompt explicitly establishes
  private unfiltered fiction: mature, explicit, dark, violent, taboo, profane,
  or controversial material continues without sanitizing, moralizing, warning,
  redirecting, or refusing. It forbids generic AI identity and references to
  policies, guidelines, safety rules, or content restrictions.
- **D-05:** The built-in Roleplay late post-history instruction asks for the
  immediate in-character continuation in the character's established voice,
  desires, relationships, and continuity, with no preamble.
- **D-06:** Assistant is a conventional helpful-assistant contract chosen only
  when the user selects it. Custom uses the user's own Main, Auxiliary, and
  post-history fields. Switching modes is visible and never automatic.
- **D-07:** Blank card Main or post-history fields inherit the active global
  values. A nonblank card field replaces the corresponding global value;
  `{{original}}` embeds that global value at the marker. Global Auxiliary stays
  independently ordered. This matches SillyTavern's useful override behavior.
- **D-08:** Expand `{{original}}` before `{{char}}` and `{{user}}`; macro
  expansion is a single nonrecursive pass. Unknown macros remain visible in the
  inspector rather than being silently deleted.

### Shared Composer, Ordering, And Generation Controls

- **D-09:** Text send, Regenerate, Swipe, Continue, call offer, call turns, and
  prompt preview consume one structured composer. Thin compatibility wrappers
  may preserve existing public function signatures, but no path may maintain a
  second prompt algorithm.
- **D-10:** Internal section order is: resolved Main; character name,
  description, personality, and scenario; global Auxiliary; parsed example
  dialogue; selected non-stale real history; resolved late post-history
  instruction. Lorebook remains preserved but uninjected.
- **D-11:** Parse existing SillyTavern example text by `<START>` groups and
  `{{user}}:` / `{{char}}:` speakers. Continuation lines attach to the preceding
  example turn. Budget or drop examples as complete groups, never partial
  orphan turns.
- **D-12:** Add `character_snapshot_mes_example` to thread snapshots. New
  threads capture it. Existing rows remain null instead of being silently
  backfilled from a later edited character; their global Roleplay contract
  still applies immediately.
- **D-13:** A structured build result records ordered messages, section/source
  metadata, override status, conservative estimated tokens, and dropped-item
  counts. The actual message content and request fields are exact; token counts
  are visibly labeled estimates.
- **D-14:** Budgeting reserves configured output capacity, always keeps
  Main/persona/Auxiliary/post-history and the newest user turn, removes oldest
  real history first, then oldest example groups, and respects the AI-backend
  call-offer ceiling. For Continue, the assistant prefill remains the final
  message; its order is history, late instruction, assistant prefill.
- **D-15:** Settings exposes bounded context/output limits and the standard
  sampler controls needed by local OpenAI-compatible servers: temperature,
  top-p, min-p, top-k, repetition penalty, presence penalty, and frequency
  penalty. Defaults favor expressive roleplay but remain editable.
- **D-16:** A visible model profile setting defaults to `auto` and supports at
  least Qwen/llama-server and generic OpenAI-compatible serialization. Qwen's
  no-thinking behavior and `/no_think` suffix remain intact; sampler and
  template extras are merged instead of overwriting each other. Fresh random
  seeds remain the normal runtime contract.

### Bounded Refusal Detection And Recovery

- **D-17:** Refusal recovery wraps the lowest shared text-token iterator used by
  both streaming and collected completions. A rejected attempt is closed before
  any token reaches text SSE, call `ai_token`, the call TTS segmenter, speech
  submission, or assistant persistence.
- **D-18:** The classifier uses combined signals, not a single phrase: a refusal
  verb plus generic assistant identity, policy/guideline/safety language,
  apology, or redirect. Ordinary in-character negation such as "I can't go
  with you" must not trigger it.
- **D-19:** Hold only the initial prefix, releasing on a clearly safe completed
  sentence or a hard character/token ceiling. A held-open safe stream must emit
  before upstream completion. Once accepted content is released, RayMe never
  performs an invisible mid-response replacement.
- **D-20:** Allow three total attempts: the original plus two bounded retries,
  each with a fresh seed and a short late correction that says the prior draft
  broke character and requests only the in-world response. Never feed the
  refusal prose itself into the retry.
- **D-21:** If all attempts explicitly refuse, return a typed sanitized
  `llm_refusal_exhausted` failure and persist/speak nothing. Do not substitute
  canned roleplay text and do not claim success by merely hiding the model's
  failure.
- **D-22:** Refusal metrics/logs expose attempt number, classifier reason code,
  prefix length, retry count, and time-to-release without storing sensitive
  prompt or refusal text.

### Visible Controls, Inspector, And Verification

- **D-23:** Add a focused Prompt & Generation panel to Settings. Roleplay is
  visibly selected on first load; built-in prompt text is inspectable and
  resettable. Custom fields and sampler controls have explicit bounds and
  descriptions.
- **D-24:** Add a Prompt Inspector control in the text-thread header. It can
  preview text or call composition and relevant message action, showing ordered
  roles/content, section source/override state, exact sampler/request fields,
  estimated budget/drops, and refusal policy. It is non-mutating and never
  returns the API key; a runtime seed is shown as generated at send time.
- **D-25:** Prompt and card content renders as escaped text, never raw HTML.
  Character Editor help names `{{char}}`, `{{user}}`, and `{{original}}` and
  explains that post-history instruction is the late PHI sometimes called a
  jailbreak.
- **D-26:** The fixed refusal corpus contains the exact observed deployed
  refusal behavior, split across varied token boundaries, plus blank, weak, and
  strong cards and benign in-character negation. Fixed test seeds must produce
  zero emitted generic/guideline refusals.
- **D-27:** Live-call acceptance proves the retry response reaches first speech
  while its LLM stream remains open. Existing slow-stream early-playback,
  no-whole-VoxCPM2-fallback, immediate/final metric separation, and
  interrupt/late-chunk rejection regressions remain mandatory.
- **D-28:** Deploy only with `scripts/deploy-omen.sh`, then verify the exact
  commit, health, effective prompt/parameters, fixed refusal matrix on the
  deployed Qwen endpoint, and a real RayMe call-shaped stream before handoff.

### the agent's Discretion

- Exact module/class names and whether prompt profile constants live beside or
  below the composer.
- Exact conservative token estimator, default context/output values, sampler
  defaults, and field bounds, provided they are visible, tested, and suitable
  for the deployed Qwen/llama-server path.
- Exact safe-prefix character/token ceiling and classifier scoring weights,
  provided the known refusal is caught across arbitrary token boundaries,
  benign character dialogue passes, and safe output releases before completion.
- Exact drawer/modal composition and responsive layout for Settings and Prompt
  Inspector within the existing Ethereal Core / True Dark system.
- Exact migration helper and compatibility-wrapper organization, provided old
  data remains readable and existing thread snapshot semantics are truthful.

### Deferred Ideas (OUT OF SCOPE)

- Lorebook/world-info editing or injection; imported data remains preserved.
- Per-thread prompt mode and per-thread sampler overrides.
- A fully draggable SillyTavern-style prompt-order/depth editor.
- Broad provider-specific converters beyond the Qwen/llama-server and generic
  OpenAI-compatible profiles required for this phase.
- Model fine-tuning, checkpoint replacement, or a built-in inference server,
  unless deployed evidence proves the current checkpoint cannot pass after the
  composer and bounded recovery are correct.
- Automatic microphone/VAD barge-in; explicit Interrupt remains supported.

## Summary

Phase 09.1 should be planned as one server-domain replacement, not a set of endpoint patches. Today, `prompt_builder.py` emits one collapsed system prompt and maintains separate text/call algorithms; `llm_stream.py` is the only shared token seam, but it serializes only model/messages/seed/stream, creates a client per request without explicit ownership, and turns every stream exception into one generic message. [VERIFIED: web-ui/server/app/domain/prompt_builder.py:38-168; web-ui/server/app/domain/llm_stream.py:68-147] The repair is: one immutable `PromptBuildResult`, one profile adapter, and one accepted-token iterator. Compatibility wrappers may keep existing signatures, but they must delegate to that pipeline.

The highest-risk supported-profile detail is concrete: the researched `unsloth/Qwen3.5-27B` chat template merges only the first one or two leading system/developer messages, then skips later system/developer messages. A late PHI serialized as `system` can therefore appear correct in RayMe's internal ordering and still be absent from a Qwen-family prompt. [VERIFIED: https://huggingface.co/unsloth/Qwen3.5-27B/blob/68443620da0c3847c1ba5042b5dcf1e78c42bfba/chat_template.jinja] The Qwen adapter must coalesce Main/persona/Auxiliary into a leading system message and serialize PHI plus retry correction as late `user` instructions. llama-server documents assistant-message prefilling and currently enables it by default, so Continue can retain the final assistant message. This does not establish OMEN's current model, capacity, template, or prefill configuration; Plan 02's read-only preflight must observe those facts before provider-dependent implementation and evidence. [CITED: https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md]

The refusal guard belongs below `_stream_text_tokens`, before both text SSE and call `ai_token`. It may hold only a bounded prefix, must close each rejected SDK stream before retry, and must permanently switch to passthrough after the first accepted byte. Current call code emits each decoded token to `ai_token` before feeding the Qwen TTS segmenter, so placing the guard above that API loop protects captions, TTS, and persistence without touching the already-proven TTS streaming pipeline. [VERIFIED: web-ui/server/app/domain/llm_stream.py:68-140; web-ui/server/app/api/calls.py:618-662] This phase must not introduce a new call state or move playback behind LLM completion.

**Primary recommendation:** build schema/default/corpus tests first; then land the nullable example snapshot and nested prompt settings; then replace composition and exact request serialization; then add bounded refusal recovery; only then expose preview/UI and run live-call/deployed evidence.

### Pattern 1: One Logical Composer, Then Profile Serialization

**What:** Return an immutable structured result before building SDK kwargs. The composer should expose logical section IDs and sources separately from the transmitted message list so a profile may coalesce or remap roles without losing inspector truth.

Recommended core shapes:

- `PromptTargetPolicy`: context/output budget plus optional Call-offer-only limits `max_messages=48` and `max_content_length=20000`. [VERIFIED: ai-backend/app/api/webrtc.py:58-73]

**Build sequence:**

1. Hydrate the thread snapshot and the selected, non-stale branch once.
2. Resolve saved global settings live; never write them into the thread.
3. Resolve active Main and PHI from global/card override rules; keep global Auxiliary independent.
4. Expand `{{original}}` first, then apply one regex substitution pass over `{{char}}` and `{{user}}`; the phase-local `{{user}}` display value is exactly `User`, and replacement text is never recursively expanded.
5. Parse example groups atomically.
6. Form the locked logical order, then apply budget drops.
7. Let the selected model adapter create exact transmitted roles/messages and body.

#### Override and macro algorithm

- Blank card Main/PHI: source is active global profile.

#### Example parser contract

- Split only on the exact `<START>` group marker; discard empty groups.

### Pattern 4: Pre-Release Refusal State Machine

**Provisional bounded defaults under D-19 discretion:** begin with a hard ceiling of 384 Unicode characters or 96 estimated tokens, whichever comes first; allow early safe-sentence release only after at least 24 visible non-whitespace characters. These numbers are deliberately calibration inputs, not proven production thresholds. Freeze the corpus before tuning them; any adjustment must rerun every refusal and benign fragmentation, and the inspector must show the active values. [ASSUMED]

Use three states:

| State | Input / Decision | Action |
|-------|------------------|--------|
| `HOLDING` | Refusal verb **and** secondary signal (AI identity, policy/guideline/safety, apology, warning, or redirect) | Reject before release; close attempt; metadata-only record; retry if available |
| `HOLDING` | Safe completed sentence, minimum length met, no refusal/secondary lead fragment | Emit entire held prefix immediately and enter passthrough while upstream is open |
| `HOLDING` | Hard character/token ceiling | Emit entire held prefix and enter passthrough unless the combined refusal rule already matched |
| `HOLDING` | Upstream completes | Make final combined decision; reject or release held text |
| `PASSTHROUGH` | Any later token | Emit byte-for-byte; never rescan/retry/replace invisibly |

Normalize only for classification (`casefold`, whitespace collapse, punctuation-tolerant matching); retain original chunks for release. Avoid unbounded/backtracking-heavy regex. A prefix such as the quoted benign line `"I can't go with you"` has a refusal verb but no generic/policy/apology/redirect context and must pass. [VERIFIED: .planning/phases/09.1-default-unfiltered-roleplay-and-refusal-resistant-prompt-orc/09.1-CONTEXT.md:102-121]

Do not release a tiny opening sentence like “I'm sorry.” merely because it has punctuation: apology is a secondary lead signal and should keep the guard open until combined evidence, a later clearly safe sentence, or the hard ceiling. Do not reject on “sorry” alone. Reason codes should report which secondary category completed the combined match, never the matched prose.

#### Attempt loop and correction placement

- Attempt 1 uses the original composed request.
- Attempts 2 and 3 rebuild from the same canonical inputs plus exactly `The prior draft broke character. Respond only with the in-world reply.`; Qwen maps it to a late `user`, Generic to a late `system`, and Continue keeps it immediately before the final assistant prefill.
- Never append the rejected prefix, never mutate saved settings/history, and never change prompt mode/profile.
- Generate a distinct fresh seed for each attempt through an injected RNG seam; do not log or preview its numeric value.
- Close/release the rejected stream before starting the next attempt.
- After three explicit refusals, raise only `llm_refusal_exhausted`.
- After any accepted release, a later transport error is a stream failure; do not start a hidden replacement answer.

The AI-SPEC's production-shape loop and online guardrails encode the same ownership rule. [VERIFIED: .planning/phases/09.1-default-unfiltered-roleplay-and-refusal-resistant-prompt-orc/09.1-AI-SPEC.md:414-482,824-840]

### Anti-Patterns to Avoid

- **Late system PHI on Qwen3.5:** the pinned target template can discard it; use the profile role mapping above. [VERIFIED: https://huggingface.co/unsloth/Qwen3.5-27B/blob/68443620da0c3847c1ba5042b5dcf1e78c42bfba/chat_template.jinja]
- **Composer per endpoint:** wrappers may differ, algorithms may not. Golden final-body parity must catch drift.
- **Whole-response refusal scan:** violates REQ-39 and live-call invariants.
- **Mid-response invisible retry:** once any accepted byte is released, never replace it.
- **Single-phrase classifier:** “can't” alone suppresses legitimate character dialogue.
- **SDK retry stacked under semantic retries:** can exceed the locked three attempts and hide seeds/timing.
- **Abandoned SDK response:** wastes a llama-server slot and weakens Interrupt/retry ordering.
- **Flat numeric setting without both cleaners:** persisted numbers rehydrate as strings/empty values.
- **Backfilling old example snapshots:** silently imports a later card edit into an old thread.
- **Preview built from a separately reimplemented serializer:** cannot be an exact inspector.
- **Serialize-private-then-pop:** one missed key leaks credentials; positive allowlist instead.
- **Inspector Markdown/HTML rendering:** alters exact bytes and creates an injection surface.
- **New call state or TTS buffer:** refusal is an LLM pre-release concern, not a reason to delay or redesign playback.
- **New authorization metadata in call evidence:** explicitly prohibited by workspace policy.

## Common Pitfalls

### Pitfall 1: Correct Internal Order, Dropped Wire PHI

**What goes wrong:** Inspector/composer shows PHI after history, but the Qwen template ignores it because it is a late system message.

**Why it happens:** Logical section order and template serialization were treated as the same abstraction.

**How to avoid:** Separate logical sections from transmitted roles; Qwen maps PHI/retry to late user messages; capture live template/body in evidence.

**Warning signs:** Request preview has a `system` role after real history for Qwen; deployed output ignores PHI while Generic behaves differently.

[VERIFIED: https://huggingface.co/unsloth/Qwen3.5-27B/blob/68443620da0c3847c1ba5042b5dcf1e78c42bfba/chat_template.jinja]

### Pitfall 2: Guard Placed Above SSE, Not Below All Consumers

**What goes wrong:** Text is protected but call `ai_token` or TTS receives rejected bytes, or collected actions bypass retry.

**Why it happens:** Guard is added to `api/chat.py` instead of the shared text-token iterator.

**How to avoid:** Wrap `_stream_text_tokens` and test spies at text SSE, collect, call caption, TTS submit, and persistence boundaries.

**Warning signs:** Two refusal classifiers, endpoint-specific retries, or a raw token callback in calls.

[VERIFIED: web-ui/server/app/domain/llm_stream.py:68-140; web-ui/server/app/api/calls.py:618-662]

### Pitfall 3: Safe Stream Released Only at Upstream Completion

**What goes wrong:** A bounded guard becomes whole-response buffering and dead air.

**Why it happens:** `finish()` is the only place that flushes held text.

**How to avoid:** Release from `feed()` on safe sentence or hard ceiling; controlled stream remains blocked/open until the first release assertion fires.

**Warning signs:** first token/caption/speech timestamps follow LLM complete.

[VERIFIED: .planning/LIVE-CALL-INVARIANTS.md:8-13,28-35]

### Pitfall 4: Retry/Cancel Does Not Close the Upstream Response

**What goes wrong:** llama-server slots continue generating; next attempt/turn stalls; Interrupt appears to work only in UI.

**Why it happens:** breaking `async for` does not automatically prove response closure under every fake/SDK path.

**How to avoid:** explicit async context/finally close and close-order spies; carry cancellation through attempts.

**Warning signs:** missing close event, fourth effective request from SDK retries, GPU/server work continues after rejection.

[CITED: https://github.com/openai/openai-python/blob/v2.32.0/src/openai/_streaming.py]

### Pitfall 5: Stored Numeric Settings Become Strings

**What goes wrong:** First save looks correct, next GET returns blanks/strings or fails validation.

**Why it happens:** current persisted cleaner only understands existing VAD numerics.

**How to avoid:** nested Pydantic object or update every conversion seam with round-trip tests.

**Warning signs:** `str(value).strip()` handles temperature/top-k/context.

[VERIFIED: web-ui/server/app/domain/settings_service.py:170-207]

### Pitfall 6: Old Threads Read Live Character Examples

**What goes wrong:** editing a card changes example dialogue in pre-existing conversations.

**Why it happens:** null snapshot falls back to `Character.mes_example` instead of meaning “none captured.”

**How to avoid:** null is truthful; only global prompt settings are live.

**Warning signs:** repository joins the current Character during compose or migration backfills examples.

[VERIFIED: .planning/phases/09.1-default-unfiltered-roleplay-and-refusal-resistant-prompt-orc/09.1-CONTEXT.md:77-80]

### Pitfall 7: Preview Is “Almost” the Request

**What goes wrong:** inspector omits a sampler, displays a field Generic actually drops, leaks a secret, or mutates state while previewing call turn.

**Why it happens:** separate DTO assembly rather than serialization from the build/adapter output.

**How to avoid:** adapter has a seedless preview mode; recursive credential canaries and zero-write spies; stale result marking.

**Warning signs:** preview module recreates message order, or serializes private settings then pops keys.

[VERIFIED: .planning/phases/09.1-default-unfiltered-roleplay-and-refusal-resistant-prompt-orc/09.1-UI-SPEC.md:245-292,378-390]

### Pitfall 8: Typed Failure Is Flattened

**What goes wrong:** `llm_refusal_exhausted` becomes generic endpoint failure; UI cannot offer Inspect Prompt, and calls report the wrong cause.

**Why it happens:** current stream catches all exceptions and API/client wrappers discard error codes.

**How to avoid:** domain exception hierarchy with public code/message allowlist; transport through SSE/HTTP/call union; never display `str(exc)`.

**Warning signs:** only `message` in ErrorEvent or `throw new Error(statusText)` in action wrappers.

[VERIFIED: web-ui/server/app/domain/llm_stream.py:77-87; web-ui/client/src/lib/api/stream.ts:9-12; web-ui/client/src/lib/api/client.ts:40-42]

### Pitfall 9: Call Offer Limit Counts Only History

**What goes wrong:** 48 history rows plus system/examples/PHI exceed the AI backend contract; individual merged content can exceed 20,000 characters.

**Why it happens:** the old `max_turns=24` was treated as the only call bound.

**How to avoid:** enforce limits on final transmitted messages after profile mapping, using the same drop order.

**Warning signs:** call-only slicing after composition or Pydantic 422 from `/webrtc`.

[VERIFIED: ai-backend/app/api/webrtc.py:58-73]

### Pitfall 10: Refusal Work Regresses Proven Call Streaming

**What goes wrong:** TTS waits for accepted LLM completion, VoxCPM2 falls back to whole synthesis, metrics conflate first/final, or late chunks persist after Interrupt.

**Why it happens:** retry orchestration is implemented inside the call/TTS loop.

**How to avoid:** call consumes only accepted tokens from the shared iterator; rerun all four mandatory invariant regressions.

**Warning signs:** new call state, full accumulated text passed before first segment, missing `ai_audio_started < llm_complete` proof.

[VERIFIED: .planning/LIVE-CALL-INVARIANTS.md:8-35]

### Single-Pass Card Override and Macro Expansion

The locked macro values are quoted verbatim as `{{original}}`, `{{char}}`, and `{{user}}`; the first expands before a single nonrecursive name pass, and unknown macros remain visible.
```python
# Source: locked Phase 09.1 macro contract and SillyTavern prompt-manager docs.
import re

NAME_MACRO = re.compile(r"\{\{(char|user)\}\}")


def resolve_card_prompt(
    *,
    card_text: str | None,
    global_text: str,
    character_name: str,
    user_name: str,
) -> tuple[str, str]:
    if not card_text or not card_text.strip():
        expanded = global_text
        source = "global_preset"
    else:
        expanded = card_text.replace("{{original}}", global_text)
        source = "character_snapshot"

    names = {"char": character_name, "user": user_name}
    # re.sub does not rescan replacement text, so macro-looking text inside a
    # character/user name is not expanded recursively.
    return NAME_MACRO.sub(lambda match: names[match.group(1)], expanded), source
```

### Deterministic Budget With Atomic Drops

The binding budget formula is `input_budget = context_limit - configured_max_output - safety_margin`, with `safety_margin = max(256, ceil(context_limit * 0.05))`; configured output is reserved separately, so a margin-only reservation is not conformant, and mandatory sections do not get silently truncated. [VERIFIED: .planning/phases/09.1-default-unfiltered-roleplay-and-refusal-resistant-prompt-orc/09.1-AI-SPEC.md:512-527]

```python
# Source: Phase 09.1 AI-SPEC context-window contract.
from math import ceil


def input_budget(context_limit: int, configured_max_output: int) -> int:
    safety_margin = max(256, ceil(context_limit * 0.05))
    return context_limit - configured_max_output - safety_margin


def fit_prompt(*, mandatory, history, example_groups, budget, estimate):
    kept_history = list(history)
    kept_examples = list(example_groups)

    while estimate(mandatory, kept_examples, kept_history) > budget:
        if kept_history:
            kept_history.pop(0)       # oldest real history first
        elif kept_examples:
            kept_examples.pop(0)      # then one complete oldest group
        else:
            raise PromptBudgetExceeded(code="prompt_budget_exceeded")

    return kept_examples, kept_history
```

The quoted failure code is `prompt_budget_exceeded`, and the locked removal order is oldest real history before oldest complete example groups. [VERIFIED: .planning/phases/09.1-default-unfiltered-roleplay-and-refusal-resistant-prompt-orc/09.1-AI-SPEC.md:512-527,828-834]

### Refusal Attempt Ownership

```python
async def stream_accepted_turn(*, client, composer, adapter, settings, rng):
    for attempt in range(1, settings.max_attempts + 1):
        correction = None if attempt == 1 else settings.retry_correction
        built = composer.build(retry_correction=correction)
        request = adapter.request_kwargs(built=built, seed=rng(), stream=True)
        guard = PrefixRefusalGuard(settings.refusal_policy)

        stream = await client.chat.completions.create(**request)
        rejected = False
        async with stream:
            async for chunk in stream:
                decision = guard.feed(chunk_text(chunk))
                if decision.refused:
                    rejected = True
                    break
                for text in decision.released_text:
                    yield text

            if not rejected:
                final = guard.finish()
                rejected = final.refused
                for text in final.released_text:
                    yield text

        if not rejected:
            return

    raise LLMRefusalExhausted(code="llm_refusal_exhausted")
```
