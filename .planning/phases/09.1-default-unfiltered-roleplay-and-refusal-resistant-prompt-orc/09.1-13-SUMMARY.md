# Phase 09.1 Plan 13: Prompt Inspector UI Summary

**A credential-free, non-mutating Prompt Inspector now exposes the exact six-action request composition, budgets, ordered messages, sampler/adapter identity, omissions, and bounded refusal metadata in an accessible 320px-to-desktop dialog.**

## Accomplishments

- Added exact discriminated preview request/response types and one abortable same-origin wrapper over Plan 08's non-mutating composer boundary.
- Delivered Text Send/Regenerate/Swipe/Continue and Call offer/Call turn controls, exact target/draft/transcript eligibility, stale-result retention, typed failures, and the seven ordered UI-SPEC result sections.
- Proved zero mutation traffic, escaped hostile input, credential/exception/rejected-prose absence, zero/one/many collection truth, abort behavior, focus ownership, and 320px containment in desktop and mobile Chromium.
- Preserved the live-call contract: no VAD/barge-in surface was added and all six protected live-call tests remain discoverable.

## Requirements Delivered (Verbatim)

- **REQ-38** `[v1]` — **Shared SillyTavern-class prompt composer**: text and
  live-call generation use one ordered, token-budgeted composer supporting
  global Main, Auxiliary, and late post-history prompts; character overrides
  with `{{original}}`; at least `{{char}}` and `{{user}}` macros; injected
  example dialogue; model-aware message roles; explicit sampler controls; and
  an exact effective-request inspector that excludes credentials. Thread
  snapshots preserve character identity but must not freeze obsolete global
  prompt defaults.
- **REQ-39** `[v1]` — **Bounded streaming refusal recovery**: RayMe detects an
  explicit generic/guideline refusal in the initial streamed prefix, cancels
  that attempt, and retries with corrective prompt context before the refused
  text is rendered, spoken, or persisted. Normal in-character output must be
  released after a small bounded prefix guard; neither text nor calls may wait
  for the full LLM response, and live-call early playback, listening recovery,
  and explicit interruption remain mandatory.

## Decisions Made

- Built every action payload in the drawer from explicit local inputs and sent it only to `/api/prompt-preview`; preview cannot reach any generation, message, settings, call, microphone, or seed-allocation handler.
- Kept target summaries visually bounded to 80 characters while retaining complete selected prompt/message content in the result.
- Used allowlisted object construction for request JSON instead of serializing the whole DTO, keeping omitted fields absent and seed fixed as **Generated at send time**.
- Preserved an earlier successful result during loading/errors and derived stale status from variant, action, target, draft, transcript, and thread identity.
